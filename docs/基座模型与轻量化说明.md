# 基座模型选择与轻量化说明

## 结论

正式研究路线把 **OpenDriveVLA-0.5B** 作为必要基座，不从零训练。选择依据是：它属于课题指定论文和代码库，输入输出与端到端驾驶轨迹任务直接对应，官方工程提供 0.5B checkpoint，较大参数 VLA 更适合课程资源，并能复用 Qwen2.5 语言能力与已有视觉—语言—动作对齐。

官方模型网址：https://huggingface.co/OpenDriveVLA/OpenDriveVLA-0.5B 。该仓库需要登录并同意访问条款。本地 checkpoint 与官方代码现已下载；`scripts/audit_opendrivevla.py` 可重复核验必需文件、Safetensors 文件头、架构与依赖。

## 当前交付与完整实验的区别

| 项目 | 当前可运行 Demo | 推荐完整实验 |
|---|---|---|
| 基础能力 | LiteVLA 轻量代理与学习参数 | OpenDriveVLA-0.5B 预训练权重 |
| 输入 | 结构化交通场景 | 多相机图像、ego state、导航指令 |
| 输出 | 12 个 waypoint 与目标速度 | 自回归 waypoint/action token |
| 训练 | NumPy SFT、Reflection 加权、轻量 DPO | LoRA/PEFT Reflection SFT + DPO/GRPO |
| 运行资源 | CPU、秒级、约 KB 参数 | GPU、nuScenes/CARLA、完整依赖链 |
| 用途 | 验证数据闭环、Critic 和交互 Demo | 验证视觉感知与真实驾驶性能 |

当前 Demo 不宣称在 Windows 进程中加载了 OpenDriveVLA 权重。代码通过 `BaseModelAdapter` 把模型边界独立出来，已支持官方六点轨迹解析、真实 GPU 输出缓存回放和 CPU 明示回退；Critic、Reflection、数据过滤、偏好对构造和评估模块保持不变。

本地轻量训练增加三轮失败经验回放，并提供 OpenDriveVLA LoRA SFT、Reflection SFT 和 DPO 的数据导出、配置及训练入口。运行 `python scripts/train_opendrivevla_peft.py --stage sft --check-only` 可在 Windows 核验训练资产；取消 `--check-only` 需要 Linux/CUDA 和官方依赖。

## 轻量化执行方案

1. 以 OpenDriveVLA-0.5B checkpoint 初始化，避免从随机参数训练视觉—语言对齐。
2. 冻结视觉编码器和大部分语言层，只训练 multimodal projector、trajectory head 与 LoRA 参数。
3. 使用 8-bit/4-bit 权重量化与梯度累积，减少显存峰值。
4. 先在离线缓存视觉特征上完成 Reflection SFT，再用小规模 chosen/rejected 轨迹对执行 DPO。
5. 用规则 Critic 作为安全硬门槛，Reward Model 只负责排序，LLM Critic 负责低频解释复核，避免昂贵模型参与每条样本。

## 论文与仓库映射

- OpenDriveVLA：基座、结构化 driving token、waypoint 输出和分阶段训练。
- UniAD：以最终规划为中心组织感知、预测和地图信息。
- DriveAgent-R1：主动感知、混合推理与结构化工具反馈。
- Alpamayo-R1：因果推理与动作一致性、SFT/RL 组合。
- Agent-Driver：工具、经验记忆和自我反思闭环。
- DeepSeek-R1：冷启动、反思强化学习与偏好优化方法论。
- DriveLM：驾驶图式问答、证据链和 nuScenes/CARLA 数据组织。
